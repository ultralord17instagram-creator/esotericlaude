# Что заменить при выкате на сервер и домен

Чеклист по порядку: сначала то, без чего сайт не поднимется, потом то, без чего
он поднимется, но будет врать пользователю или поисковикам.

Отмечать можно прямо здесь.

---

## 1. Домен и инфраструктура

### 1.1 `nginx/prod.conf` — заменить `YOUR_DOMAIN` в четырёх местах

| Строка | Что там |
|---|---|
| 23 | `server_name` HTTP-блока |
| 40 | `server_name` HTTPS-блока |
| 45 | путь к `fullchain.pem` |
| 46 | путь к `privkey.pem` |

Пути к сертификатам должны совпадать с доменом, который вы передадите certbot,
иначе nginx не найдёт файлы и не стартует.

### 1.2 SSL-сертификат

```bash
./scripts/ssl_init.sh ваш-домен.ru admin@ваша-почта.ru
```

Запускать после того, как DNS домена уже указывает на сервер и nginx поднят на
80 порту: certbot проверяет владение доменом по HTTP.

### 1.3 `.env` в корне репозитория

Скопировать из `.env.example` и заполнить:

| Переменная | Значение |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | `https://ваш-домен.ru`, **с протоколом и без слэша на конце** |
| `DATABASE_URL` | реальный PostgreSQL |
| `AUTH_SERVICE_URL`, `AUTH_SERVICE_API_KEY` | у команды партнёрки |
| `OFFER_ID` | у команды партнёрки |
| `PAYMENT_SERVICE_URL`, `PAY_FORM_URL` | у команды партнёрки |
| `DEBUG` | **`false`**. При `true` наружу открыт `/docs` со схемой API |
| `NEXT_PUBLIC_YANDEX_VERIFICATION`, `NEXT_PUBLIC_GOOGLE_VERIFICATION` | коды из вебмастеров, см. раздел 4 |

### 1.4 `frontend/.env`

| Переменная | Значение |
|---|---|
| `NEXT_PUBLIC_OFFER_ID` | ID оффера |
| `NEXT_PUBLIC_PAYMENT_BACK_URL` | `https://ваш-домен.ru/lk` |
| `NEXT_PUBLIC_CP_PUBLIC_ID` | Public ID из кабинета CloudPayments |
| `PS_URL`, `PS_API_KEY` | Payment Service партнёрки |
| `TS_URL`, `TS_API_KEY` | Tracking Service партнёрки |
| `ADMIN_PASSWORD` | свой пароль для `/admin` |

`BACKEND_URL` руками не трогать: в проде его задаёт `docker-compose.prod.yml`
как `http://backend:8000`.

### 1.5 Ветка в `scripts/deploy.sh`

Скрипт делает `git pull origin main`. Основная ветка репозитория называется
`master`, а работа сейчас идёт в `feat/astrix-homepage-redesign`. Либо влить
изменения в ту ветку, которую тянет скрипт, либо поправить строку в скрипте.

## 2. Домен вшивается в сборку, а не читается в рантайме

`NEXT_PUBLIC_SITE_URL` это `NEXT_PUBLIC_*`-переменная: её значение попадает
в JavaScript-бандл **на этапе сборки**. Задать её только в окружении
работающего контейнера недостаточно.

Из неё строятся не только canonical и `sitemap.xml`, но и **адреса внутри
юридических документов**: ссылки на оферту, политику и адрес сайта в тексте
оферты собираются из `SITE_URL`. Забыли поменять — в договоре останется
`astrix.ru` из заглушки.

После любой смены домена:

```bash
docker compose -f docker-compose.prod.yml build frontend
```

Проверить, что домен доехал: `https://ваш-домен.ru/sitemap.xml`, в `<loc>`
должен быть ваш домен, а не `localhost` и не `astrix.ru`.

## 3. Юридические документы

Все реквизиты и цены живут в двух файлах, по документам они не размазаны.

### 3.1 `frontend/app/legal/operator.js`

Заполнено: наименование ИП, ИНН, ОГРНИП, почта поддержки.

**Не заполнено: почтовый адрес регистрации ИП.** В исходных данных его не было.
Поля в объекте пока нет вовсе. Понадобится при подключении эквайринга или по
требованию партнёрки: добавить в `OPERATOR` и строкой в `REQUISITES`, и адрес
появится сразу на `/info`, `/offer`, `/terms` и `/privacy`.

### 3.2 `frontend/app/legal/tariffs.js`

Объявлены: Пробный 7 ₽ / 7 дней, Основной 299 ₽ / 7 дней, Особый 99 ₽ / 2 дня.

Эти суммы напечатаны в оферте, то есть являются публичным обещанием цены. Они
обязаны совпадать с тарифом, настроенным в кабинете партнёрки. Проверить после
выката:

```bash
curl https://ваш-домен.ru/api/v1/subscriptions/tariff
```

`first_amount` и `amount` из ответа должны совпасть с числами в файле. Не
совпали — правим файл (и пересобираем фронт), а не документы: из этого файла
цену берут одновременно оферта, условия предоставления услуг, страница
`/tariff`, пейволл и кнопка в личном кабинете.

### 3.3 Даты редакций

`REVISION` в трёх файлах (`terms.content.js`, `offer.content.js`,
`privacy.content.js`) и `TARIFFS_APPROVED` в `tariffs.js` стоят на 10 августа
2026 года. Перед публикацией поставить реальную дату утверждения.

### 3.4 Телеграм поддержки

Сейчас во всех документах контакт один: почта из `operator.js`. Если появится
телеграм-канал поддержки, заменить в четырёх местах:

- `privacy.content.js`: пункт 8.4 (отзыв согласия), 12.1 (разъяснения), пункт 9
  формы согласия
- `offer.content.js`: пункт 6.1 (отмена подписки)
- `tariff/page.jsx`: блок «Отмена подписки»
- `cancel/CancelClient.jsx`: текст на экране после отправки

### 3.5 Розыгрыш призов

Пункт 2.7 оферты обещает розыгрыш не реже раза в 365 дней с фондом до 50 000 ₽
и вручением до 31 декабря. Пункт перенесён из присланного шаблона. Если
проводить розыгрыш не планируется, пункт убрать: это обязательство, а не текст
для красоты.

### 3.6 Спорный пункт про возврат

Пункт 3.9 оферты говорит, что после открытия доступа возврат не производится.
Против потребителя это не работает: статья 32 ЗоЗПП даёт право отказаться в
любой момент. Пункт оставлен как в присланном шаблоне, но при обращении
в Роспотребнадзор или к банку возврат придётся сделать.

## 4. SEO

### 4.1 Картинка для соцсетей

`frontend/public/og.png` (1200×630) сейчас заглушка с полумесяцем без текста.
Заменяется простой подменой файла, код править не нужно.

### 4.2 Коды подтверждения в вебмастерах

1. Добавить сайт в Яндекс.Вебмастер и Google Search Console.
2. Взять значение атрибута `content` из предложенного метатега.
3. Вписать в `NEXT_PUBLIC_YANDEX_VERIFICATION` и `NEXT_PUBLIC_GOOGLE_VERIFICATION`.
4. Пересобрать фронт (переменные тоже build-time).
5. Подтвердить права, отправить `sitemap.xml` в обоих кабинетах.

### 4.3 Что проверить

- `https://ваш-домен.ru/robots.txt` отдаётся, `Host` и ссылка на sitemap с вашим доменом
- `https://ваш-домен.ru/sitemap.xml` отдаётся, внутри 25 адресов с вашим доменом
  (17 статических страниц плюс 8 лендингов `/lp/*`)

## 5. Форма отмены подписки

`/cancel` это **заглушка**: форма валидирует поля и показывает экран «Заявка
принята», но никуда ничего не отправляет. Место для запроса помечено `TODO`
в `handleSubmit` в `frontend/app/cancel/CancelClient.jsx`.

Когда появится приёмник заявок:

1. Написать отправку в `handleSubmit`.
2. Дописать первые 6 и последние 4 цифры карты в перечень обрабатываемых данных
   в `privacy.content.js` (раздел 6 и пункт 3 формы согласия). Сейчас их там
   нет, потому что мы их не собираем.
3. Убедиться, что цифры карты не попадают в логи.

До этого момента страница обещает пользователю отмену в течение 24 часов,
которую физически никто не получит. Либо подключить приёмник, либо убрать
ссылку из подвала.

## 6. Проход после выката

Открыть и глазами проверить:

| Адрес | Что смотрим |
|---|---|
| `/` | подвал на месте, ссылки на документы кликаются |
| `/offer` | домен в тексте ваш, цены совпадают с кабинетом партнёрки |
| `/terms` | 11 пунктов, цены те же |
| `/privacy` | 13 разделов, форма согласия в конце |
| `/tariff` | три тарифа, те же суммы |
| `/info` | реквизиты ИП |
| `/cancel` | форма открывается |
| `/register` | чекбокс согласия, обе ссылки открываются в новой вкладке |
| `/checkout` | цена на форме оплаты совпадает с ценой в документах |
| `/sitemap.xml`, `/robots.txt` | ваш домен |

Отдельно: убедиться, что `https://ваш-домен.ru/docs` **не открывается**. Если
открывается, в `.env` остался `DEBUG=true`.

---

## 7. Режим техработ

Включается и выключается из `/admin` (пароль из `ADMIN_PASSWORD`), ставит куку
`maintenance_mode` и уводит всех на `/maintenance`. Раздел `/admin`, `/api` и
сам `/maintenance` при этом продолжают работать.
