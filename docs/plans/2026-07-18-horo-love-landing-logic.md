# Лендинг «Любовь» (гороскопы) — логика

Дата: 2026-07-18. Статус: согласовано (концепция), логика к реализации.

> Только логика. Визуал/вёрстка/стили делаются отдельно в Claude Design и в этот
> документ не входят.

## 1. Цель и суть

Прелендинг-воронка для CPA под продукт «Гороскопы», аудитория женская (ЖЦА).
Один лендинг `/lp/horo-love` с развилкой на входе из трёх эмоциональных
состояний. Каждое состояние это своя ветка со своим байтом, квизом и ревилом.
Целевое действие везде одно: регистрация (как в love/him).

Три ветки:

| id ветки | Состояние (её выбор) | Байт |
|---|---|---|
| `suzheny` | «Жду своего человека» | кто он: знак, приметы, 🔒 первая буква имени, 🔒 месяц встречи |
| `return` | «Не могу отпустить одного» | что у него в голове, 🔒 вернётся ли и когда, 🔒 что сделать |
| `block` | «У меня не складывается» | твой любовный блок, 🔒 сценарий и 🔒 как снять |

Принцип байта: **свободная часть строит веру конкретикой**, ключевое (буква
имени, месяц, вердикт «вернётся», как снять блок) под замком → регистрация.

## 2. Архитектура и роутинг

- Новый движок `horo-love`, конфиг `content/landings/horo-love.js`
  (`engine: 'horo-love'`, `product: 'horoscope'`).
- Роутинг в [page.jsx](frontend/app/lp/[slug]/page.jsx): добавить ветку
  `landing.engine === 'horo-love' ? HoroLoveClient : ...`.
- Клиент `frontend/app/lp/[slug]/HoroLoveClient.jsx` (фазовый, по образцу
  `CompatClient`/`RevealClient`).
- Чистая логика (тестируемая через `node:test`, без React):
  `frontend/app/lp/logic/horoLove.js`.
- Контент-пулы: `frontend/app/content/horoscope/love/` (тексты по веткам и знакам).

Переиспользуем как есть (только плумбинг, без визуала):
`Hero`, `Quiz`, `QuizStep`, `Calculating`, `Paywall`, `useTracking`,
`saveQuiz/loadQuiz/clearQuiz`, `safeReturnPath`, `sign()`,
`seedFromName()`/`prng()`, `interpolate()`, `normalizeName()`.

## 3. Вход: развилка и диплинк

Два способа зайти в ветку:

1. **Экран-развилка** (широкий трафик): 3 варианта состояния → выбор ставит
   `branch` и ведёт в квиз ветки. Это первый микро-коммитмент и самосегментация.
2. **Диплинк** (заточенный трафик под конкретный креатив): `?v=<branch>` в URL
   (`suzheny|return|block`) сразу ставит `branch` и **минует развилку**, чтобы не
   терять совпадение посыла (message match).

Резолвинг ветки на маунте:
```
const v = searchParams.get('v')
branch = ['suzheny','return','block'].includes(v) ? v : null
phase = branch ? 'quiz' : 'fork'
```
Невалидный/пустой `v` → развилка. Выбранная ветка кладётся в answers и в
`saveQuiz`, чтобы возврат после оплаты восстановил именно её.

## 4. Машина состояний (фазы)

По образцу `CompatClient`:

```
fork ─(выбор|диплинк)→ quiz ─(complete)→ calculating ─(done)→ reveal ─→ paywall
                                                                   │
                                          (isSubscribed на возврате)└→ full
```

- `fork` — выбор состояния (пропускается при диплинке).
- `quiz` — шаги ветки (`landing.branches[branch].quiz.steps`) → её дата рождения
  (+ имя для `suzheny`/`block`; + тап-выбор его знака для `return`).
- `calculating` — `Calculating` со строками ветки (`branches[branch].calcLines`).
- `reveal` — генерим значения (см. §5), показываем free-поля + замки на locked.
- `paywall` — `Paywall` ветки (`branches[branch].paywall`) → регистрация.
- `full` — тот же ревил, но locked-поля раскрыты (для подписанного на возврате).

Возврат после оплаты (как в `CompatClient`): на маунте, если `isSubscribed` и
`loadQuiz('horo-love')` содержит `branch` + ответы → восстановить, посчитать
значения, `phase='full'`. Не подписан → обычный вход в воронку.

## 5. Детерминированный генератор (ядро)

Модуль `logic/horoLove.js`. Всё чисто и стабильно: один и тот же вход всегда даёт
один результат (важно, чтобы при повторном заходе «суженый» не менялся и не
рушил доверие).

**Сид:**
```
seed = seedFromName(`${normalizeName(name)}|${birthDate}|${branch}`)
rand = prng(seed)           // mulberry32 из revealMachine.js
pick = (arr) => arr[Math.floor(rand() * arr.length)]  // порядок вызовов фиксирован
```
`branch` в сиде, чтобы одна девушка в разных ветках не получила один и тот же
набор. Порядок `pick()`-вызовов детерминирован кодом → результат стабилен.

**Её знак:** `herSign = sign(birthDate)` (id, name, element).

**Совместимость по стихиям** (новая таблица, не матрица-нумерология). Из
`element` в `astro.js`:
- Огонь↔Воздух и Земля↔Вода — гармония (score 3);
- та же стихия — притяжение (3);
- соседние — рабочие (2);
- квадрат (Огонь↔Вода, Огонь↔Земля, Воздух↔Земля, Воздух↔Вода) — напряжение (1).

Таблица `ELEMENT_SCORE[a][b]` симметрична. Даёт ранжирование 12 знаков под её
знак (для `suzheny`) и «лин» вердикта (для `return`).

### 5.1 Ветка `suzheny` — генерируемые поля
Вход: `herSign`, `seed`. Поля (free = вера, locked = добивание):

| поле | free/locked | источник |
|---|---|---|
| `hisSign` | free | `pick()` из топ-совместимых знаков по `ELEMENT_SCORE` |
| `ageHint` | free | `pick(AGE_POOL)` (старше/младше/ровесник) |
| `character` | free | 2–3 черты из `TRAITS[hisSign.id]` |
| `meetHow` | free | `pick(MEET_POOL)` (где/через кого) |
| `firstLetter` | 🔒 | `pick(INITIALS_POOL)` (курируемый пул инициалов) |
| `meetMonth` | 🔒 | месяц из `1..12` смещения от `seed` → название месяца |
| `howYouKnow` | 🔒 | `pick(RECOGNIZE_POOL)` |
| `almostObstacle` | 🔒 | `pick(OBSTACLE_POOL)` |

### 5.2 Ветка `return` — генерируемые поля
Вход: `herSign`, `hisSign` (её тап, без даты), ответы квиза, `seed`.

| поле | free/locked | источник |
|---|---|---|
| `hisState` | free | пул по `hisSign` + тон ответов |
| `whyDistant` | free | `pick(DISTANT_POOL)` |
| `willReturn` | 🔒 | вердикт (да/сложно/нет-но) от `ELEMENT_SCORE(her,his)` + ответы |
| `whenReturn` | 🔒 | окно/условие возврата |
| `whatToDo` | 🔒 | `pick(WHATTODO_POOL[hisSign.element])` |

### 5.3 Ветка `block` — генерируемые поля
Вход: `herSign`, ответы квиза, `seed`.

| поле | free/locked | источник |
|---|---|---|
| `blockName` | free | название сценария из `BLOCKS[herSign.element]` (эффект узнавания) |
| `howItShows` | free | как проявляется |
| `rootScenario` | 🔒 | откуда он (родовой/детский сценарий) |
| `howToRelease` | 🔒 | как снять |
| `whenClears` | 🔒 | когда откроется путь |

## 6. Модель гейтинга (free / teaser / замок)

Каждая ветка объявляет `revealFields: [{ id, label, locked }]`. Генератор
возвращает `values` со всеми полями. Клиент:
- free-поля рендерит текстом;
- locked-поля рендерит как «замок» с `label` (без значения);
- в `phase='full'` (подписан) раскрывает locked-значения.

Значения locked считаются всегда (чтобы `full` их показал без пересчёта), но до
оплаты не отдаются в разметку значений (только label). Так тизер честный: ярлык
виден, содержимое закрыто.

## 7. Стык с оплатой (конверсия = регистрация)

Полное переиспользование `Paywall`:
- `Paywall` пишет `post_checkout_return = /lp/horo-love` и ведёт на `/register`
  (или `/lk`, если уже залогинен).
- После оплаты продукт возвращает на лендинг; `safeReturnPath` уже ограничивает
  редиректы шаблоном `/lp/<slug>`.
- На возврате подписанный + сохранённые ответы → `phase='full'` (награда: полный
  ревил показан прямо на лендинге).

Диплинк-ветку тоже надо восстановить: `branch` лежит в `saveQuiz`, `post_checkout_return`
достаточно базового `/lp/horo-love` (ветка берётся из хранилища, не из URL).

## 8. Хранилище и трекинг

**Хранилище** (`quizStorage`, ключ `lp_quiz_horo-love`):
`{ branch, ...quizAnswers, birth_date, name?, his_sign? }`.

**События** (`track(event, { slug:'horo-love', branch, ... })`), по образцу
существующих:
- `lp_view` (маунт),
- `fork_select` (новое, `{ branch }`) или `deeplink_enter` при диплинке,
- `quiz_start`, `quiz_complete`,
- `reveal_view`,
- `paywall_view`,
- `cta_click` (уже шлёт `Paywall`).

## 9. Крайние случаи

- Нет имени (ветки `return`/`block` могут не спрашивать имя): сид от `date|branch`.
- `return`: `his_sign` обязателен (тап по знаку), без него из квиза не выйти.
- Повторный заход без подписки: вход заново с fork/quiz (как `CompatClient`,
  который восстанавливает только подписанного). Значения всё равно совпадут
  (детерминизм).
- Невалидный `?v=` → развилка.
- SSR: генератор чистый, но вызывать после ввода на клиенте; `loadQuiz`/`localStorage`
  под `typeof window` (уже так в `quizStorage`).

## 10. Тесты (node:test, как соседние `*.test.mjs`)

- Детерминизм: один вход → идентичные `values` (все ветки).
- `ELEMENT_SCORE` симметрична и покрывает все пары стихий.
- `suzheny`: `hisSign` всегда из топ-совместимых; `firstLetter` из пула;
  `meetMonth` в диапазоне месяцев.
- Гейтинг: разбиение полей на free/locked соответствует `revealFields`.
- Резолвинг входа: валидный/невалидный `?v=` → правильные `branch`/`phase`.
- Round-trip хранилища: `saveQuiz`→`loadQuiz` восстанавливает `branch` и ответы.
