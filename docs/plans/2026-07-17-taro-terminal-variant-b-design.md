# Дизайн: /lp/taro-terminal, вариант B (возврат к сути оригинала)

Дата: 2026-07-17
Статус: согласован в брейншторме, ожидает финального go на реализацию.
Предшественники: [2026-07-16-taro-terminal-design.md](2026-07-16-taro-terminal-design.md), [2026-07-16-taro-terminal-implementation.md](2026-07-16-taro-terminal-implementation.md).

## Контекст и проблема

Оригинальная мини-игра «Таро Терминал» (PDF, 61 кадр, автор @nastasya_and_cards) устроена как **терминал-гид к физической карте в руках игрока**. Экран не показывает карту ни на одном кадре: карта лежит перед игроком (своя колода или 6 карт из Telegram), а экран даёт инструкции и открытые вопросы для саморефлексии. Ответы игрок формулирует сам (в уме или записывает), результат игры — «одна мысль о своём состоянии, которую ты сформулируешь в конце». Монетизация в оригинале мягкая: лид на личный разбор у таролога, без подписки.

Текущая реализация (движок `terminal`) перенесла тексты почти дословно, но потеряла суть:
1. Карта видна только на `reveal`, а на вопросах `q1`/`q2` исчезает — при том что все вопросы построены на всматривании в карту.
2. Открытые вопросы заменены на 4 тап-варианта, часто не совпадающие с выпавшей картой.
3. Финал «запиши свою мысль» заменён на собранный из тапов тизер и paywall.

**Вариант B** возвращает суть оригинала (свободный ввод, карта на экране, честный инсайт) и одновременно усиливает «байт» к регистрации.

## Принятые решения (развилки брейншторма)

1. **Ввод ответа**: блок-тег (обязательный выбор) + необязательное поле «своими словами». Для быстрого q3 — только тап.
2. **Байт-тизер**: цитаты игрока + строка-страховка по карте (Барнум) + мысль-афоризм. Свободный текст **никогда не интерпретируется семантически**, только цитируется или прячется.
3. **Граница бесплатное/платное**: мысль-афоризм и отражение отдаём даром, замок ставим на «что делать» (что именно и с чего начать).
4. **Длина**: 2 вопроса (блок + своё) + 1 быстрый вопрос-тап + экран «терминал анализирует» перед выводом. Наращиваем воспринимаемую глубину и вклад, а не усилие.
5. **Карты**: полные трактовки не нужны. Курируем пул карт под каждое состояние (вариант «а») + keyword-якорь из `deck.js`.
6. **Финал**: экран-paywall лендинга с ценой убираем; reading ведёт на регистрацию; цена и PayWall — на основном сайте.

## Флоу и фазы

```
boot → select → intro → pause → draw → reveal → q1 → q2 → q3 → analyze → reading → [/register]
```

Изменения против текущего движка:
- Добавлены фазы `q3` (быстрый вопрос-тап) и `analyze` (псевдо-обработка).
- Фаза `paywall` лендинга удалена. Роль «продающего» момента берёт на себя блок-замок на `reading`.
- Прогресс-строка и `STEP 0X-07` пересчитываются под новое число содержательных шагов (было 7, станет 8: intro, pause, draw, reveal, q1, q2, q3, analyze/reading). Точный маппинг уточняется при реализации.

## Экраны (изменения относительно текущего)

- **reveal** (без изменений по сути): карта прилетает и переворачивается, подпись «римский номер · имя». Карта сохраняется в состоянии и дальше не размонтируется.
- **q1 / q2**: карта закреплена (компактно, всегда видна). Вопрос в открытой формулировке оригинала. Ниже — блоки-теги (4 варианта, обязателен выбор одного) и необязательное однострочное поле «опиши своими словами» с плейсхолдером. Кнопка «Далее» активна после выбора блока (текст не обязателен).
- **q3**: карта закреплена. Вопрос + 3-4 тап-варианта, без поля ввода. Кнопка активна после выбора.
- **analyze** (новый): терминальная псевдо-обработка. Печатаются строки лога («считываю ответы… сверяю с картой {имя}… сопоставляю состояние…»), короткий прогресс, затем авто-переход на `reading` (~1.5-2.5 c; при reduced-motion мгновенно). Игрок ничего не делает.
- **reading**: карта закреплена. Открытый вывод печатается по слоям. Ниже — блок-замок «РАЗБОР ЗАКРЫТ» (blur) и список «что откроется» (буллеты без цены). Кнопка «Что с этим делать →» ведёт на `/register` (или `/lk`, если уже авторизован).

Раскладку рисует пользователь (Claude Design). Требование от логики: место под закреплённую карту на `reveal → q1 → q2 → q3 → reading`.

## Модель состояния (TerminalClient)

- `phase` — фаза (см. флоу).
- `stateId` — выбранное состояние.
- `card` — вытянутая карта (из курированного пула, см. ниже). Живёт от `draw` до `reading`.
- `a1Tag`, `a1Text` — тег и свободный текст ответа 1.
- `a2Tag`, `a2Text` — тег и свободный текст ответа 2.
- `a3` — выбранный вариант ответа 3.
- существующие: `drawing`, `flipped`, `secs`, `typed`, `reduced`.

## Схема данных (taro-terminal-copy.js), per state

```
{
  id, menuLabel, intro, pause,
  q1: { prompt, blocks: [4 строки], placeholder },
  q2: { prompt, blocks: [4 строки], placeholder },
  q3: { prompt, options: [3-4 строки] },
  cardPool: [номера карт из TERMINAL_DECK, курированные под это состояние],
  teaser: {
    quote1,     // шаблон с {a1Tag}/{a1Text}
    quote2,     // шаблон с {a2Tag}/{a2Text}
    cardLine,   // шаблон-Барнум с {cardRu} и {cardKw} (keyword-якорь)
    thought,    // мысль-афоризм (бесплатный инсайт)
    lock        // «что делать», уходит под замок
  }
}
```

Большая часть текстов уже есть в текущем `taro-terminal-copy.js` (промпты, thought, teaserLock), их переразложим по слотам. Новое: `q3` для каждого состояния, `placeholder` полей, `cardPool`, разделение цитат на quote1/quote2 с поддержкой тега и текста.

## Логика движка (terminalMachine.js)

- **PHASES** обновить: добавить `q3`, `analyze`; убрать `paywall`.
- **BACK_PHASES** пересмотреть (назад доступен на intro…q3; на analyze/reading — нет).
- **pickCard(stateId, rand)**: выбирает случайную карту **из `cardPool` состояния**, а не из всех 10. Фолбэк на весь `TERMINAL_DECK`, если пул пуст. Тесты передают детерминированный `rand` и явную колоду (как сейчас).
- **isMeaningful(text)**: грубый порог осмысленности свободного текста. Правило: `trim().length >= 12` (или содержит пробел и >= 6 символов). Никакого семантического анализа. Ниже порога — текст в тизере не используется.
- **buildTeaser(state, card, a1, a2)** где `a1 = {tag, text}`, `a2 = {tag, text}`:
  - `open[0]` = quote1 с тегом; если `isMeaningful(a1.text)` — добавить «Твоими словами: „{a1.text}"».
  - `open[1]` = quote2 с тегом (+ опц. текст a2 по тому же правилу).
  - `open[2]` = cardLine (Барнум, `{cardRu}` + `{cardKw}` из `card.keywords`).
  - `open[3]` = thought (мысль-афоризм).
  - `lock` = lock-шаблон («что делать»).
  - Токены-цитаты подставляются в кавычках, падеж не важен (прямая речь). Фолбэк: пустой/мусорный текст → строка с текстом опускается, тизер стоит на теге.

## Пример сборки (состояние «Я устала», карта Башня)

Вход: `a1 = {tag: "перегруз", text: "люди, которые падают"}`, `a2 = {tag: "пауза", text: ""}`, `a3 = "…"`.

Открытая часть:
```
Самым тяжёлым ты назвала «перегруз». Твоими словами: «люди, которые падают».
А опорой для тебя стало «пауза».
Карта Башня про тебя говорит: рушится не ты, а то, что держалось на пределе.
Не всякая усталость лечится усилием. Иногда отдых и есть действие.
```
Замок:
```
Что именно у тебя сейчас на пределе и с какого шага начать ▓▓▓▓  РАЗБОР ЗАКРЫТ
```
Здесь `a2.text` пуст, поэтому строка «твоими словами» для второго ответа опущена — тизер всё равно осмыслен за счёт тега «пауза».

## Курирование карт (черновой маппинг, на выверку копирайтером)

Колода 10 арканов: 4 Император, 5 Иерофант, 7 Колесница, 10 Колесо, 13 Смерть, 15 Дьявол, 16 Башня, 17 Звезда, 18 Луна, 19 Солнце.

| Состояние | Пул карт (номера) | Логика |
|---|---|---|
| Я устала | 13, 10, 4, 18, 16 | отпускание, циклы, опора, туман, предел |
| Мне страшно | 18, 15, 16, 13 | страхи, тень, внезапность, конец |
| Я запуталась | 18, 10, 16, 5 | неясность, кружение, слом, ориентир |
| Не могу выбрать | 7, 10, 5, 4 | воля, судьба, ценности, структура |
| Всё остановилось | 13, 10, 18, 16 | конец этапа, цикл, застой, слом старого |
| Хочу услышать себя | 17, 18, 5, 19 | надежда, подсознание, наставник, ясность |
| Не отпускает человек | 15, 13, 18, 17 | привязанность, отпускание, иллюзии, исцеление |
| Не понимаю, чего хочу | 19, 17, 7, 4 | витальность, мечта, движение, что важно |

Светлые карты (Солнце, Звезда) не попадают в «тёмные» состояния — это убирает диссонанс «яркая картинка ↔ мрачный текст». Значения-трактовки не пишутся: `cardLine` использует только имя и один keyword.

## Что не меняется

Каркас фаз boot/select/intro/pause/draw, анимация тасовки и переворота, CRT-хром, статус-строки, трекинг воронки (`lp_view`, `game_start`, `state_select`, `card_drawn`, `q*_answer`, `reading_view`, `cta_click`), переход на регистрацию с сохранением `post_checkout_return`.

## Тесты

- **terminalMachine.test.mjs**: `pickCard` тянет только из пула состояния (детерминированный rand); `isMeaningful` (границы порога); `buildTeaser` собирает 3-4 слоя, корректно опускает цитату текста ниже порога, подставляет keyword-якорь.
- **taro-terminal-copy.test.mjs**: у всех 8 состояний есть `q1/q2.blocks` (4), `q3.options` (3-4), все слоты `teaser`, непустой `cardPool` из валидных номеров `TERMINAL_DECK`; отсутствие длинного тире в текстах (правило проекта).

## Открытые вопросы / вне скоупа v1

- Микрореакции терминала между шагами («Принято. Идём глубже ▸») — опциональный полиш, не в первой версии.
- Полные значения карт для «полного разбора» — контент основного сайта (за paywall), не часть лендинга.
- Точный маппинг `STEP 0X-07` под новое число шагов — уточнить при реализации.
