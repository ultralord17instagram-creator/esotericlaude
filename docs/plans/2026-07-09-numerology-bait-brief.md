# Бриф на байт-тексты: продукт «Нумерология»

**Дата:** 2026-07-09
**Для:** отдельного чата Claude Code, который пишет байт-тексты (крючки для конверсии)
**Статус:** механика реализована. Ты **только заполняешь массивы строк** в одном файле
`frontend/app/content/numerology/bait.js`. Код, компоненты, остальные тексты не трогаешь.

> Документ самодостаточный. Ниже всё: что это, куда писать, каким тоном, сколько и как проверить.

---

## 1. Что такое байт-текст и где он показывается

У продукта три сценария (Разбор, Совместимость, Прогноз). Каждый разбит на **направления**
(блоки). Одно направление в каждом сценарии бесплатное, остальные платные.

Когда пользователь **без подписки** выбирает **платное** направление, он попадает на экран
результата и вместо настоящего толкования видит **байт-текст** — короткий сильный крючок, который
цепляет и подводит к кнопке «Смотреть полный разбор» (по ней всплывает окно подписки).

Твоя задача: на каждое платное направление дать несколько **сильных** крючков.

Важно: байт-текст это **не гадание и не толкование**. Это крючок-интрига. Он не обязан быть
привязан к конкретному числу (пользователь этого не сверяет). Настоящие толкования пишутся
отдельным брифом и лежат в других файлах — их не трогай.

---

## 2. Единственный файл, который ты правишь

```
frontend/app/content/numerology/bait.js
```

Структура (уже создана, с плейсхолдер-пустыми и несколькими заполненными массивами):

```js
export const BAIT = {
  breakdown:      { karma: [], ancestry: [], talents: [], love: [], money: [ ... ] },
  compatibility:  { passion: [ ... ], daily: [ ... ], money: [ ... ], fidelity: [ ... ], conflict: [ ... ], future: [ ... ] },
  forecast_month: { love: [], money: [], focus: [], warning: [ ... ] },
  forecast_year:  { love: [], money: [], challenge: [], advice: [] },
}
```

Каждый ключ направления это **массив строк** (несколько вариантов). Ты дописываешь варианты в
пустые массивы и, если нужно, усиливаешь уже заполненные. Больше ничего в файле не меняй
(ни ключи, ни структуру, ни комментарии сверху).

**Выбор варианта:** движок сам выбирает один вариант из массива детерминированно по числу
пользователя. Поэтому **все варианты одного направления должны быть взаимозаменяемы** — годиться
любому человеку, без «для числа 5...». Пиши общими формулировками.

---

## 3. Сколько вариантов

- **3 варианта на каждое платное направление.** Минимум 2, лучше 3. Они должны отличаться заходом
  (разный первый крючок), но держать один тон и тему направления.
- Всего платных направлений **19** (см. таблицу §6). Итого ориентир **~57 строк**.

---

## 4. Тон и правила (жёстко)

- **Тон:** тревога и срочность. Крючок создаёт ощущение, что происходит что-то важное прямо сейчас,
  и это нельзя откладывать. Намекай на скрытое, на риск упустить, на «окно, которое закрывается».
- **Длина:** 2–4 предложения. Коротко, плотно, без воды. Каждое предложение усиливает предыдущее.
- **Структура крючка:** (1) тревожный факт/намёк → (2) ставка, что на кону → (3) толчок узнать сейчас.
- **Обрыв на самом интересном.** Крючок ведёт к платному, поэтому он **не даёт ответа**, только
  обостряет вопрос. Никогда не раскрывай суть («причина в том, что...») — до этого подписка.
- **Обращение на «ты»** (в совместимости допустимо «вы»/«вас» про пару).
- **Без длинного тире.** Пользователь читает «—» как AI-tell. Только запятые, двоеточия, скобки,
  обычный дефис. Это жёсткое правило, проверяется автоматически.
- **Кавычки внутри текста только «ёлочки»**, не прямые. Апострофы избегай (строки в одинарных
  кавычках в JS).
- **Без markdown**, обычный текст в одной строке.

### Этические границы (не переступать)
- Никаких обещаний конкретных событий как факта («в среду он изменит», «тебя уволят 5 числа»).
  Пиши про риск, тенденцию, скрытое напряжение, не про свершившийся факт.
- Не пугай здоровьем, смертью, болезнями, деньгами-катастрофой без возврата.
- Не называй реальных людей и поступки. «Один из партнёров», «близкий человек», обобщённо.
- Цель крючка — любопытство и лёгкая тревога, а не паника и не угроза.

## 5. Тон-анкоры (эталон стиля, уже в файле)

Ориентируйся на эти как на планку силы и тона:

**compatibility.fidelity (Шанс измен):**
> «Один из партнёров уже что-то скрывает, и началось это недавно. Числа показывают, откуда тянется
> холод и что важно понять сейчас, пока трещина не стала разрывом.»

**breakdown.money (Деньги и достаток):**
> «В твоём денежном сценарии есть скрытый тормоз, из-за которого суммы утекают в одну и ту же дыру.
> Пока ты его не видишь, он повторяется из года в год, и с возрастом цена ошибки только растёт.»

**forecast_month.warning (Предостережение):**
> «В этом месяце тебя ждёт момент, где легко совершить ошибку, которую потом трудно исправить.
> Числа называют и день, и повод, чтобы ты успел подстелить соломку.»

## 6. Платные направления, которым нужен байт

Ключи = id в `bait.js`. Free-направления (destiny, general, mood/theme, день прогноза) байта **не
имеют** и в файле отсутствуют — не добавляй их.

### Разбор (breakdown) — про одного человека, «ты»
| ключ | название | угол тревоги |
|---|---|---|
| `karma` | Кармический урок | повторяющийся сценарий, который тянется из прошлого и мешает сейчас |
| `ancestry` | Ресурс рода | родовая опора, к которой ты не подключён, и что из-за этого теряешь |
| `talents` | Таланты | сильная сторона, которую ты не используешь и которая простаивает |
| `love` | Любовь и отношения | как ты сам мешаешь себе в близости, не замечая этого |
| `money` | Деньги и достаток | скрытый денежный тормоз, потолок доходов *(анкор готов)* |

### Совместимость (compatibility) — про пару, «вы»/«вас»
| ключ | название | угол тревоги |
|---|---|---|
| `passion` | Страсть и близость | притяжение гаснет по скрытому правилу, один остывает *(анкор готов)* |
| `daily` | Быт и повседневность | мелочи копятся и вот-вот взорвутся *(анкор готов)* |
| `money` | Деньги | тянете в разные стороны, решения за спиной *(анкор готов)* |
| `fidelity` | Шанс измен | один уже что-то скрывает, доверие рушится тихо *(анкор готов)* |
| `conflict` | Конфликты | ссоры ходят по кругу, есть фраза-детонатор *(анкор готов)* |
| `future` | Перспектива союза | развилка: вместе на годы или тихо разойтись *(анкор готов)* |

### Прогноз, месяц (forecast_month) — «ты»
| ключ | название | угол тревоги |
|---|---|---|
| `love` | Отношения в этом месяце | назревает поворот в близости, который легко упустить |
| `money` | Деньги и работа | окно/риск в финансах, о котором ты пока не знаешь |
| `focus` | Фокус месяца | главная тема, мимо которой ты рискуешь пройти |
| `warning` | Предостережение | момент, где легко совершить дорогую ошибку *(анкор готов)* |

### Прогноз, год (forecast_year) — «ты»
| ключ | название | угол тревоги |
|---|---|---|
| `love` | Любовь в этом году | тема отношений разворачивается не так, как ты ждёшь |
| `money` | Деньги и работа | финансовый сценарий года, который решается в начале |
| `challenge` | Вызов года | главный урок, который проще провалить, чем заметить |
| `advice` | Совет | то, что важно успеть сделать, пока год не ушёл |

## 7. Как проверить свою работу

1. **Формат.** Файл `bait.js` должен остаться валидным JS: массивы строк в одинарных кавычках,
   запятые между элементами. Ничего кроме содержимого массивов не менял.
2. **Правила.** Ни одного «—» (длинного тире). Внутри строк только «ёлочки». Без markdown.
3. **Каждый платный ключ** из §6 непустой (2–3 варианта). Free-ключей в файле нет.
4. **Прогон тестов** (структуру не ломает):

   ```bash
   docker compose -f docker-compose.dev.yml run --rm --no-deps \
     -w /app/app/content/numerology frontend node --test
   ```

   Ожидаемо: все тесты PASS (тест `getBait` проверяет, что заполненные направления
   возвращают реальный текст, а не плейсхолдер).

5. **Глазами** (стек поднят): открыть платное направление гостем, например
   `http://localhost/numerology/compatibility` → «Шанс измен». Должен показаться байт-текст и кнопка
   «Смотреть полный разбор», по клику всплывает окно подписки.
