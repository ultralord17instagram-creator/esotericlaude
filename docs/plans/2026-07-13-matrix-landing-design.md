# Дизайн: квиз-лендинг «Матрица судьбы» (партнёрская воронка, вариант A)

**Дата:** 2026-07-13
**Статус:** дизайн согласован, готов к этапу планирования реализации
**Продукт:** Матрица судьбы (первый; каркас переиспользуется под Таро, нумерологию, гороскоп)

## 1. Контекст и цель

Продукт продаётся через партнёрскую (CPA) сеть. Чтобы партнёрам было проще лить
трафик на конкретный продукт, под каждый продукт нужна **отдельная посадочная
страница** с вовлекающим «байтом», а не общая главная.

Лендинг ловит холодный трафик, за 30-60 секунд прогревает человека через квиз,
показывает частичный персональный результат и упирается в пейвол. Оплата — это
**та же подписка**, что и на основном сайте: человек получает доступ сразу ко
всем сервисам. Отдельные лендинги нужны только как маркетинговые точки входа.

Механика байта: **квиз-воронка (вариант A)** из рассмотренных на брейншторме
(A квиз / B инстант-тизер / C крючок-под-боль). Квиз даёт самый сильный прогрев,
а вариант C впоследствии получается почти бесплатно как его тематическая вариация.

## 2. Ключевые решения (согласованы с заказчиком)

1. **Монетизация:** подписка как есть (399₽/мес, 7 дней бесплатно), доступ ко
   всему сразу. Лендинг греет к оформлению.
2. **Роут:** `/lp/matrix` через динамический сегмент `/lp/[slug]`, управляемый
   конфигом. Основной сайт и текущая страница `/matrix` не затрагиваются.
3. **Механика:** квиз с вопросом про «запрос» (что волнует), для персонализации
   тизера.
4. **Глубина бесплатного тизера:** диаграмма матрицы + блок `personality` +
   заблюренный блок под запрос пользователя.
5. **Хендофф в оплату:** ответы квиза сохраняются в `localStorage`, после оплаты
   полный разбор открывается сразу, без повторного ввода.
6. **Дизайн лендингов:** рисуется заказчиком в Claude Design, каждый лендинг
   может выглядеть полностью иначе, чем сайт и другие лендинги. Самостоятельный
   конструктор лендингов (вариант B из обсуждения) в скоуп НЕ входит.

## 3. Роут и шаблонизация

- Файл страницы: `app/lp/[slug]/page.jsx` (динамический роут).
- Конфиг лендинга: `app/content/landings/matrix.js` — hero-копия, шаги квиза,
  правила тизера, акцент пейвола под запрос. Добавить новый продукт = добавить
  такой конфиг (тот же принцип, что и в `app/products.config.js`).
- Отдельный `layout` для группы `/lp/*` **без основной навигации сайта**: на
  лендинге не должно быть путей «убежать», только воронка.
- Атрибуция партнёра: `?ref=CODE` уже перехватывается на любой странице через
  `RefTracker` (localStorage + TTL). Отдельная работа не требуется, нужно лишь
  донести ref через цепочку лендинг → регистрация → оплата.

## 4. Организация дизайн-макетов

Макеты из Claude Design (`.dc.html`) складываются в
`design-reference/landings/<продукт>/` (см. README там же). Это отделено от
`design-reference/*-reference/`, где лежат макеты страниц самого сайта.
Разработчик переносит согласованный макет в рабочий лендинг на `/lp/<продукт>`.

## 5. Воронка end-to-end

Одностраничная стейт-машина (шаги переключаются на клиенте, без перезагрузок):

1. **Hero (шаг 0):** сильный заголовок + подзаголовок + мягкий соц-пруф, одна
   кнопка «Пройти тест». Никакой навигации, единственный CTA.
2. **Квиз (шаги 1..N):** один вопрос на экран, прогресс-бар, микро-коммитменты.
3. **Анимация расчёта:** «Строим твою матрицу...», 2-3 сек, нагнетает ожидание.
4. **Тизер результата:** персональная шапка + реальная диаграмма + 1 бесплатный
   блок + заблюренные замки под запрос.
5. **Пейвол:** оффер подписки с акцентом под запрос, CTA в регистрацию/оплату.
6. **Хендофф:** `/register` → `/checkout`; после оплаты полный разбор открыт
   сразу.

## 6. Квиз: шаги

1. **Дата рождения** — функциональный вход, кормит `calculateMatrix`.
2. **Пол** — для тона обращения.
3. **«Что сейчас волнует больше всего?»** — Деньги / Отношения / Предназначение /
   Таланты и самореализация. Задаёт персонализацию тизера.
4. **Мягкая шкала-прайминг** — «Насколько ощущаешь, что живёшь не свою жизнь?»
   (1-5). Микро-коммитмент, усиливает боль.
5. **Имя** — для персонализации результата. Email здесь НЕ спрашиваем, чтобы не
   резать конверсию; он собирается при регистрации.

## 7. Тизер результата: что бесплатно, что под замком

Движок `calculateMatrix(birthDate)` и контент `MATRIX_CONTENT[center]` уже дают
нужную структуру (`app/content/matrix.js`, `app/content/matrix-content.js`).

- **Бесплатно:** диаграмма (`MatrixSVG`) + персональная шапка (`MatrixHeader`) +
  блок `personality` (он уже во `FREE_ASPECTS`).
- **Под замком (заблюрено, видно превью первых строк):** блок, соответствующий
  запросу пользователя из шага 3, плюс список остальных платных аспектов. Человек
  видит именно свою тему, но обрезанную.

## 8. Персонализация по запросу

Ответ шага 3 маппится на существующие аспекты контента (важно: варианты ответа
должны иметь соответствующий блок, иначе будет пусто):

| Запрос                     | Аспект (`ASPECT_LABELS`)      |
|----------------------------|-------------------------------|
| Деньги                     | `money`                       |
| Отношения                  | `relationships`               |
| Предназначение             | `personalPurpose`             |
| Таланты и самореализация   | `talents`                     |

Этот аспект: (а) заголовок пейвола («полный разбор денежного канала + доступ ко
всем сервисам»), (б) тот самый заблюренный блок в тизере.

## 9. Пейвол и хендофф в оплату

- Переиспользуем `app/components/ui/Paywall.jsx`, добавив акцент под запрос.
- Ответы квиза (дата, пол, запрос, имя) сохраняем в `localStorage` (напр. ключ
  `lp_quiz_matrix`), чтобы пережить редиректы `лендинг → /register → /checkout`.
- После успешной оплаты (пользователь `subscribed`) полный разбор показывается
  сразу: результат восстанавливается из сохранённых ответов, без повторного
  ввода даты рождения.

## 10. Переиспользуемые компоненты

`calculateMatrix`, `MatrixSVG`, `MatrixHeader`, `MatrixInterpretations` (уже
гейтит по `isSubscribed`), `Paywall`, `Modal`, атмосферный фон
(`Particles` / `Aurora` / `StarField`).

**Новое:** движок квиза (шаги/прогресс/состояние), hero-экран, экран анимации
расчёта, конфиг лендинга, layout группы `/lp/*`.

## 11. Трекинг воронки

`useTracking().track(event, body)` шлёт `POST /api/tracking/[event]`, то есть
можно добавить свои события воронки: `lp_view`, `quiz_start`, `quiz_step`
(с индексом), `quiz_complete`, `teaser_view`, `paywall_view`, `cta_click`.
`?ref=` уже привязывает партнёра к сессии.

## 12. Открытые технические зависимости (проверить на этапе планирования)

1. **Трекинг:** роут `app/api/tracking/[event]` и бэкенд-трекер (TS) должны
   пропускать новые типы событий воронки. Иначе аналитика по шагам не соберётся.
2. **Хендофф:** страница/вью полного результата должна уметь восстановиться из
   `localStorage` (сейчас `/matrix` требует ручного ввода в форму).
3. **Оплата:** сверить фактическую цепочку `/register` → `/checkout` →
   активация подписки (`usePayment`, `CheckoutClient`), чтобы ref и контекст
   квиза не терялись.

## 13. Вне скоупа (YAGNI сейчас)

Самостоятельный конструктор лендингов, email-капча в квизе и ретаргет брошенных
воронок, отдельный поддомен, тематические боль-вариации (вариант C), A/B-фреймворк.
Всё это второй заход после того, как базовый квиз-каркас заработает и начнёт
конвертить.
