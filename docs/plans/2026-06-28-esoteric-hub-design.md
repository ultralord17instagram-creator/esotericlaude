## 1. Концепция

Один сайт — много эзотерических сервисов. Пользователь может попробовать каждый продукт **бесплатно в демо-режиме**, полный результат доступен по подписке. Продажа происходит внутри продукта (пейвол), а не на лендинге.

## 3. Расширяемость продуктов

Продукты описываются в едином конфиг-файле `products.config.ts`. Добавить новый продукт = добавить объект в конфиг + реализовать логику расчёта. Вся обвязка (карточка, страница, пейвол, форма ввода, режим «для другого») переиспользуется автоматически.

```ts
// products.config.ts — структура объекта продукта
{
  id: 'matrix',
  name: 'Матрица судьбы',
  slug: 'matrix',
  icon: '...',
  inputs: ['birth_date'],          // базовые поля из профиля
  extraInputs: [],                 // доп. поля, специфичные для продукта
  freeResult: MatrixFreeResult,    // компонент демо-результата
  paidResult: MatrixPaidResult,    // компонент полного результата
}
```

**Прицел на будущее:** продукты переносятся в БД и управляются через админку (без изменения кода).

## 4. Модель доступа

| Уровень | Что видит |
|---|---|
| Без регистрации | Демо-результат каждого продукта |
| Зарегистрирован, без подписки | Демо-результат + данные сохранены в профиле |
| Подписчик | Полный результат всех продуктов |

### Бесплатный демо-режим (Вариант Б)
Каждый продукт имеет два компонента результата: `FreeResult` (демо, доступен всем) и `PaidResult` (полный, только подписчикам). Пейвол появляется после показа демо прямо внутри продукта.

## 5. Флоу пользователя

```
Лендинг
  → Попробовал продукт (без регистрации, данные вводятся инлайн)
    → Увидел демо-результат
      → Пейвол: «Хочешь полный результат?»
        → Регистрация (обязательна при оплате)
          → Оплата
            → ЛК + полный доступ ко всем продуктам
```

### Регистрация
- Поля: email + пароль + имя + дата рождения + пол
- Опциональна до момента оплаты
- При регистрации данные сохраняются в профиль

### Без регистрации
- Продукт спрашивает нужные данные инлайн (имя, дату рождения и т.д.)
- Данные используются в моменте, не сохраняются

### Режим «Проверить другого»
- У каждого продукта есть переключатель: «Для себя» / «Для другого»
- «Для себя» — данные подтягиваются из профиля
- «Для другого» — вводятся вручную, не сохраняются

### Доп. данные продукта
- Некоторые продукты требуют специфичные данные (время рождения, место, фото руки)
- Запрашиваются инлайн при открытии продукта
- Используются в моменте, не сохраняются в БД

## 6. Данные: что где хранится

### Партнёрка (auth_service) — не трогаем
- Email, пароль, username
- `access_token` / `refresh_token` (HttpOnly cookies)
- Статус подписки, история платежей
- `referral_code` (атрибуция вебмастера)

### Локальная БД оффера

**Таблица `users`** (уже существует):
| Поле | Тип | Описание |
|---|---|---|
| `id` | UUID | Локальный PK |
| `auth_user_id` | UUID | Связь с партнёркой |
| `referral_code` | VARCHAR(64) | Атрибуция |
| `created_at` | TIMESTAMPTZ | — |
| `updated_at` | TIMESTAMPTZ | — |

**Таблица `user_profiles`** (новая):
| Поле | Тип | Обязательное |
|---|---|---|
| `auth_user_id` | UUID (FK → users) | ✅ |
| `name` | VARCHAR | нет |
| `birth_date` | DATE | нет |
| `gender` | ENUM (male, female) | нет |

**История запросов и результатов — не хранится.** Всё используется в моменте.

## 9. Лендинг

### Структура (Вариант C — гибрид)
1. **Hero** — сильный заголовок, суть сервиса, CTA «Попробовать бесплатно»
2. **Превью продуктов** — карточки каждого продукта, можно попробовать прямо здесь
3. **Как это работает** — 3 шага: попробуй → убедись → открой полный доступ
4. **Отзывы** — социальное доказательство
5. **Footer**

### Принципы
- Без агрессивных продаж на лендинге — продукт говорит сам за себя
- Продажа происходит внутри продукта (пейвол после демо)
- Каждая секция — отдельный компонент, структуру легко менять перестановкой

## 11. Дизайн-система

### Стиль
Светлый минималистичный, Apple-образный: много пространства, чистая типографика, лаконичные карточки. Не перегружен мистикой визуально — контент говорит за себя.

### Токены (CSS-переменные)
Все цвета, шрифты и отступы — в одном файле `app/styles/theme.css`.  
**Смена темы = правка одного файла.**

```css
/* app/styles/theme.css */
:root {
  /* Цвета */
  --color-bg: #ffffff;
  --color-surface: #f5f5f7;
  --color-text-primary: #1d1d1f;
  --color-text-secondary: #6e6e73;
  --color-accent: #0071e3;
  --color-border: #d2d2d7;

  /* Типографика */
  --font-sans: 'Inter', system-ui, sans-serif;
  --font-size-base: 17px;
  --line-height-base: 1.6;

  /* Отступы */
  --radius-sm: 8px;
  --radius-md: 12px;
  --radius-lg: 20px;
  --spacing-section: 80px;
}
```
