# Дизайн: лендинг Таро «на него» (движок live-reveal)

Статус: согласовано (brainstorming), готов к плану реализации.
Связанные документы: [копи-бриф](2026-07-15-taro-live-reveal-copy-brief.md).
Продукт: расклад Таро (`product: 'tarot'`), платный полный разбор за пейволом.

## Задача

Под партнёрскую сеть нужен байт-лендинг на продукт «Расклад Таро», отличный от того, что уже есть:
- не квиз (love/him уже квизовые),
- не «просто вытяни карту» (это и так живёт на основном сайте, `/tarot`).

Нужна новая механика с максимальным байтом под ниши «он/бывший» и «страх/паттерны».

## Концепт (в чём байт)

Новый движок `live-reveal`: кинематографичный расклад, который разворачивается сам и обрывается на вопросе, который выбрала сама пользовательница. Отличие от расклада на основном сайте:
1. Персонализация на конкретного мужчину (ввод его имени).
2. Она сама выбирает главный вопрос (само-вовлечение, вопрос-крючок и закрытая карта это одно и то же).
3. Карты открываются сами, толкование печатается вживую и называет его по имени.
4. Открытые карты бьют Барнум-точностью (её ощущения, его внутреннее состояние), а не проверяемыми фактами.
5. Финальная карта (её вопрос) закрыта на замок, текст обрывается на полуслове (эффект Зейгарник) → пейвол.

## Пользовательский флоу (фазы)

`hero → input → attuning → reveal → lock → paywall`

1. hero: крючок + выбор вопроса (4 варианта). Тап по вопросу запускает расклад.
2. input: ввод его имени (только имя).
3. attuning: переиспользуем `Calculating` с тарологическими строками, «настройка колоды на него».
4. reveal: 3 карты открываются по очереди, печатающийся именной текст (Барнум, по 2 предложения).
5. lock: 4-я карта (выбранный вопрос) закрыта, текст обрывается, блюр.
6. paywall: переиспользуем `Paywall`, общие 4 выгоды, CTA в существующую воронку регистрации/оплаты.

Событийная воронка (tracking): `lp_view → question_select → name_submit → reveal_complete → paywall_view → cta_click`.

## Архитектура и встройка в движок

Точка расширения та же, что у `compat-jealous`:
- `frontend/app/lp/[slug]/page.jsx`: добавить ветку `landing.engine === 'live-reveal'` → новый `RevealClient` (сейчас там выбор между `CompatClient` и `LandingClient`).
- Конфиг лендинга в `frontend/app/content/landings/taro-him.js`, регистрация в `frontend/app/content/landings/index.js` (`LANDINGS`).
- Всё клиентское, бэкенд не трогаем (как love/him). Полный платный расклад открывается уже в ЛК/продукте после оплаты.

## Схема конфига (live-reveal)

Остаются общие поля `slug`, `product`, `engine`, `theme`, `meta`, `hero`, `paywall`. Новое:

- `input`: `{ mode: 'name', field: { id: 'his_name', placeholder, ... } }` (задел под `mode: 'charge'` для второй ниши).
- `questions`: массив выбираемых вопросов. Каждый: `{ id, label, lockTitle, cards: [ {position, text}, {…}, {…} ], lockText }`. Тексты с токеном `{name}` (только именительный падеж).
- `reveal`: параметры показа (кол-во открытых карт = 3, позиция замка = последняя, тайминги/пейсинг).

Тексты выносим в отдельный файл `taro-him-copy.js` (как `him-copy.js`), конфиг импортирует из него. Это НЕ боевые толкования из `content/tarot/texts` (их не палим, они за пейволом).

## Логика карт (детерминизм)

- Колода и картинки переиспользуются: `frontend/app/content/tarot/deck.js` (22 аркана) и статика `frontend/public/cards/*.png`, компонент `frontend/app/tarot/components/TarotCard.jsx`. Новых ассетов нет.
- Подбор карт детерминированный: сид от нормализованного имени. Одно имя → тот же расклад (ощущение настоящего, при повторе не разваливается). Без дублей карт в раскладе.
- Чистая логика в `frontend/app/lp/logic/revealMachine.js`: нормализация/сид имени, детерминированный выбор N карт без дублей, модель позиций и позиция замка, переходы фаз.

## Копирайт

Полный текст в [копи-брифе](2026-07-15-taro-live-reveal-copy-brief.md). Ключевое:
- Тон максимально жёсткий (ревность, страх потери), но веришь.
- Правило Барнума: никаких проверяемых событий, только её ощущения и его внутреннее состояние.
- Крючок на первом экране ничего не presume про их статус.
- Имя `{name}` только в именительном падеже, иначе брак склонения.
- Без длинного тире (пользовательское правило проекта).

Новое:

- `frontend/app/lp/components/LiveReveal.jsx` — покартное открытие с печатающимся текстом и замком.
- `frontend/app/lp/logic/revealMachine.js` (+ `revealMachine.test.mjs`).
- `frontend/app/content/landings/taro-him.js` — конфиг.
- `frontend/app/content/landings/taro-him-copy.js` (+ тест формы, как `index.test.mjs`).
- Классы в `frontend/app/lp/lp.module.css`.

## Данные, трекинг, возврат после оплаты

- Имя хранится локально (`quizStorage`), на бэкенд не уходит для байта.
- Пейвол-CTA как в `Paywall`: пишет `post_checkout_return = /lp/${slug}`, ведёт в `/lk` (если залогинен) или `/register`.
- Возврат после оплаты: подписан + сохранённое имя → уводим в ЛК к полному раскладу.
- Трекинг по фазам через `useTracking().track` (события выше).

## Обработка крайних случаев

- Пустое/мусорное имя: валидация, обрезка длины, фильтрация эмодзи для отображения и сида.
- `prefers-reduced-motion`: показываем reveal сразу, без потоковой печати и долгих анимаций.
- Прогрессивный рендер: hero и input работают без тяжёлой анимации.
- Модерация рекламы: держим смягчённый вариант крючка в брифе (блок A/B).

## Тестирование

Юнит-тесты чистой логики (`.test.mjs`, конвенция проекта):
- детерминизм подбора карт по имени и отсутствие дублей,
- позиция замка,
- нормализация/санитизация имени,
- переходы фазовой машины.
Плюс тест формы конфига `taro-him` (наличие обязательных полей, `{name}` в текстах веток).

## Масштабирование под партнёрку

- Вторая ниша (страх/паттерны) = второй конфиг того же движка: `input.mode = 'charge'` (зарядка колоды пальцем вместо имени), подбор тяжёлых арканов, свои тексты. Продаёт `shadow`/`ancestral`.
- Дальше семейство растёт добавлением конфигов, без изменения движка.

## Вне рамок (сейчас не делаем)

- Реальные боевые толкования на лендинге (остаются за пейволом, в продукте).
- Ввод её имени/даты (решено: только его имя).
- Per-ветка отдельные выгоды на пейволе (решено: общие 4).
- Механика второй ниши (charge) реализуется отдельным шагом после флагмана.
